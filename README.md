# Gorpils — экспорт опубликованного сайта

GitHub Pages: <https://hippi44.github.io/gorpils/>.

Публичный лендинг: <https://gorpils-landing-20261110.vercel.app/>.
Он размещён в отдельном production-проекте Vercel `gorpils-landing-20261110`
и не требует входа. Идентификаторы нового проекта — в
`vercel-export/landing.json`.

Полная копия файлов, доступных в деплое
<https://gorpils-client-preview-20261105.vercel.app/>.

**Это готовая статическая сборка, а не исходный Astro-проект.**
В текущем и двух предыдущих деплоях отсутствуют компоненты `.astro`,
`package.json`, исходный TypeScript и история Git. Восстановить оригинальный
проект из этих деплоев невозможно: для него нужен исходный репозиторий или архив.
Переменные окружения Vercel в этот экспорт не входят.

## Содержимое

- `site/` — 71 файл сайта: пять HTML-страниц, CSS, шрифты, изображения,
  документ, favicon, robots.txt и sitemap.xml. Байты файлов не изменены.
- `vercel.json` — конфигурация размещения статической копии на Vercel.
  Сохранены все восемь правил маршрутизации, редиректы, CSP, остальные
  заголовки безопасности, настройки кеширования и страница 404.
- `vercel-export/config.json` — оригинальная конфигурация Build Output API v3.
- `vercel-export/manifest.json` — список всех 72 скачанных файлов, их размеры,
  исходные идентификаторы, SHA-1 и SHA-256.

Все 72 файла проверены: SHA-1 скачанного содержимого совпадает с идентификатором
файла в Vercel. Локальные ссылки и ресурсы всех HTML-страниц присутствуют.
На публичном лендинге проверены все 71 файл сайта: ответы побайтово совпадают
с локальной копией. Также проверены редиректы, обработка 404 и заголовки
безопасности. В браузере проверено переключение вкуса пастилок.

## Локальный просмотр

Из корня репозитория:

```powershell
python -m http.server 8000 --directory site
```

Откройте <http://localhost:8000/>. Этот простой сервер показывает файлы,
но не воспроизводит заголовки, редиректы и обработку 404 из конфигурации Vercel.

## Размещение на Vercel

Импортируйте репозиторий в **новый** проект Vercel. Конфигурация `vercel.json`
выбирает статический сайт, отключает установку зависимостей и сборку и задаёт
выходную папку `site`. Node.js, npm и Astro для этой копии не нужны.

Оригинальный проект Vercel и опубликованный сайт при экспорте не изменялись.
Исходный URL на момент экспорта защищён входом в Vercel. Эта защита относится
к настройкам платформы и не переносится вместе с файлами или `vercel.json`.
Настройте Deployment Protection отдельно, если копия также должна быть закрытой.
Публичный репозиторий открывает доступ ко всем файлам, включая документы.

Поскольку скопированы настройки preview-деплоя, сайт сохраняет
`X-Robots-Tag: noindex, nofollow, noarchive`. Для индексируемого production-сайта
эту настройку нужно пересмотреть отдельно.

## GitHub Pages

Второй независимый адрес: <https://hippi44.github.io/gorpils/>.
Workflow `.github/workflows/pages.yml` проверяет и публикует сайт при изменении
файлов сайта, скрипта сборки или тестов в ветке `main`. Его также можно запустить
вручную через GitHub → Actions → Deploy GitHub Pages → Run workflow.

`scripts/build_github_pages.py` создаёт отдельную папку `_pages/`: добавляет
префикс `/gorpils/` к локальным ссылкам, изображениям, srcset и CSS-шрифтам,
переносит canonical/Open Graph/JSON-LD/sitemap на домен GitHub Pages и проверяет
наличие локальных ресурсов. Файлы `site/` и настройки Vercel не изменяются.
Изображения, шрифты и документ копируются без изменения содержимого.

Локальная проверка и сборка, без установки зависимостей:

```powershell
python -m unittest discover -s tests -v
python scripts/build_github_pages.py
```

Папка `_pages/` — генерируемый артефакт, она не коммитится.
GitHub Pages использует страницы `instruction/index.html`, `privacy/index.html`,
`terms/index.html` и собственную обработку `404.html`. Конфигурация `vercel.json`
там не применяется: пользовательские HTTP-заголовки и правила кеширования
Vercel GitHub Pages не переносит. Исходные HTML-настройки `noindex` сохранены.
Для публикации не нужен токен Vercel: workflow использует стандартный
`GITHUB_TOKEN` и OIDC с ограниченными разрешениями.

## Доступ к API

Токены не должны находиться в репозитории. На компьютере владельца токен Vercel
сохранён в пользовательской переменной Windows `VERCEL_TOKEN`. Он доступен
локальным инструментам с правами этого пользователя, но не нейросетям в браузере
или на другом компьютере. Инструкция по локальному доступу находится вне проекта:
`%USERPROFILE%\VERCEL_ACCESS.md`.

Пользовательские переменные Windows не шифруются. Если токен был отправлен
в чат, рекомендуется отозвать его в Vercel и заменить новым.
